# Развёртывание METU-портала на Vercel

## 1. Сначала замените старый API-ключ

Ранее ключ OpenRouter находился в публичном `index.html`. Считайте его скомпрометированным:
1. Откройте https://openrouter.ai/keys.
2. Отзовите старый ключ.
3. Создайте новый ключ. Не вставляйте его в HTML, JavaScript или GitHub.

Удаление ключа из последней версии файла не удаляет его из истории Git, поэтому отзыв обязателен.

## 2. Импортируйте репозиторий в Vercel

1. Откройте https://vercel.com/new и войдите через GitHub.
2. Выберите репозиторий `Jarv1s-stack/metu_rus_silabus`.
3. В настройках проекта укажите:
   - Framework Preset: **Other**
   - Root Directory: **./**
   - Build Command: оставить пустым
   - Output Directory: **.** (корень репозитория)
4. Нажмите Deploy.

Сайт — обычный статический HTML, а AI работает через серверную функцию `api/chat.js`. Отдельный Express-сервер и сборка фронтенда не нужны.

## 3. Добавьте секреты в Vercel

Откройте **Project → Settings → Environment Variables** и добавьте:

| Name | Value |
| --- | --- |
| `OPENROUTER_API_KEY` | Новый ключ из OpenRouter |
| `OPENROUTER_MODEL` | `nvidia/nemotron-3.5-lightning:free` |

Для ключа выберите Production, Preview и Development. Сохраните переменные и выполните **Deployments → Redeploy**. Переменные окружения применяются к новым деплоям.

## 4. Проверка

1. Откройте домен Vercel.
2. Перейдите во вкладку **ИИ-консультант**.
3. Спросите, например: «Какие темы входят в первый модуль весеннего силлабуса?»
4. Проверьте, что ответ ссылается на нужный силлабус и неделю.

Если появляется сообщение о ненастроенном ИИ, проверьте имя переменной `OPENROUTER_API_KEY`, её значение и повторно запустите деплой.

## 5. Локальный запуск (необязательно)

1. Скопируйте `.env.example` в `.env.local`.
2. Впишите новый ключ в `.env.local`.
3. Установите Vercel CLI и запустите из папки проекта:

```bash
npm install -g vercel
vercel dev
```

Не загружайте `.env.local` в GitHub. Файл уже добавлен в `.gitignore`.

## Важно

ИИ через `/api/chat` будет работать на Vercel. На GitHub Pages серверной функции нет, поэтому чат на прежнем GitHub Pages адресе не сможет обращаться к этому API. Бесплатная модель OpenRouter может иметь лимиты и временные сбои.
